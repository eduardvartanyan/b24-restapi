# Проект "Ремонт ТС": чеклист приемки

Дата создания: 2026-06-17
Дата актуализации: 2026-07-29

Этот чеклист используется для проверки, что настройка CRM-воронки в Битрикс24 готова к работе по текущей версии ТЗ.

## 1. Воронка и карточка сделки

- [ ] Создана отдельная воронка "Ремонт ТС".
- [ ] Созданы все согласованные стадии.
- [ ] Созданы обязательные поля клиента и ТС.
- [ ] В карточке сделки используется контакт клиента.
- [ ] Создано отдельное поле "СТОА" с привязкой к компании CRM.
- [ ] В поле "СТОА" выбирается компания с типом "СТОА".
- [ ] Стандартное поле "Клиент" не используется для выбора СТОА.
- [ ] Отдельные поля мастера, адреса СТОА, даты и времени дефектовки в сделке не создаются.
- [ ] Созданы поля результата дефектовки.
- [ ] Созданы поля контроля ремонта.
- [ ] Созданы поля проверки качества.
- [ ] Созданы поля расчетов и комиссии.
- [ ] Обязательность полей настроена по стадиям.
- [ ] Зафиксировано, что портал работает в облаке на тарифе "Профессиональный".

## 2. Справочник СТОА

- [ ] Создан тип CRM-компании "СТОА".
- [ ] В карточке СТОА хранится название.
- [ ] В карточке СТОА хранится адрес.
- [ ] В карточке СТОА хранятся телефоны.
- [ ] В карточке СТОА хранится график работы.
- [ ] В карточке СТОА хранятся условия комиссии.
- [ ] В карточке СТОА указан ответственный.
- [ ] В карточке СТОА хранится комментарий.
- [ ] В тестовом контуре заведены две СТОА.
- [ ] Для каждой тестовой СТОА заведены по два экстранет-пользователя и ресурса онлайн-записи.
- [ ] Подготовлена инструкция для самостоятельного создания СТОА, экстранет-пользователей, ресурсов и графиков.

## 3. Онлайн-запись и мастера

- [ ] Подтверждена доступность онлайн-записи на текущем тарифе.
- [ ] Настроена тестовая услуга "Дефектовка ТС".
- [ ] Мастера настроены как ресурсы бронирования или специалисты.
- [ ] Тип ресурса каждого специалиста точно совпадает с названием его СТОА.
- [ ] Название ресурса содержит имя мастера.
- [ ] Менеджер определяет СТОА каждого специалиста по типу ресурса.
- [ ] В профиле каждого мастера заполнен мобильный телефон.
- [ ] В профиле каждого мастера заполнен уникальный ID ресурса онлайн-записи.
- [ ] В профиле каждого мастера указана CRM-компания СТОА.
- [ ] Каждый ресурс сопоставляется ровно с одним активным экстранет-пользователем.
- [ ] Экстранет-пользователь не может изменить авторитетное сопоставление со своим ресурсом.
- [ ] У каждого мастера есть отдельный график приема.
- [ ] У каждого мастера есть видимая занятость.
- [ ] Менеджер видит доступные окна мастеров.
- [ ] Менеджер может записать клиента вручную из CRM-сделки.
- [ ] В поле сделки фиксируется СТОА.
- [ ] В связанной онлайн-записи фиксируются специалист, дата и время дефектовки.
- [ ] Специалист, дата, время и адрес СТОА доступны шаблонам задач, срокам контрольных задач и сообщениям без ручного дублирования.
- [ ] При переносе, смене мастера или отмене записи связанные задачи и уведомления актуализируются.
- [ ] REST-обработчик запускается при создании онлайн-записи.
- [ ] Запись не создает конфликтов и двойных бронирований.
- [ ] Клиент получает подтверждение записи через каскадную рассылку.
- [ ] Клиент получает напоминание о визите через каскадную рассылку.

## 4. Задачи мастеру и результат дефектовки

- [ ] После записи на дефектовку задача создается непосредственно на найденного экстранет-пользователя.
- [ ] Текст задачи содержит марку и модель ТС, госномер, ФИО клиента, телефон, дату и время, описание повреждений.
- [ ] В теле задачи указан стандартизированный формат ответа мастера.
- [ ] Мастер получает уведомление о новой записи через каскадную рассылку.
- [ ] Мастер получает ссылку на автоматически созданную задачу через каскадную рассылку.
- [ ] Мастер может оставить комментарий к задаче.
- [ ] Ответ мастера содержит результат, комментарий и ориентировочную стоимость либо отметку "не определена".
- [ ] Ответственный вручную переносит результат и комментарий в поля сделки.
- [ ] Ответственный переносит ориентировочную стоимость в сделку, если она определена.
- [ ] По результату "отказался" сделка уходит в "Отказ / неуспешно".
- [ ] По результату "не приехал" ответственному ставится задача связаться с клиентом.
- [ ] По результату "думает" сделка уходит в "Клиент думает".
- [ ] По результату "согласился на ремонт" сделка уходит в "Контроль начала ремонта".

## 5. Контроль ремонта и проверка качества

- [ ] На стадии "Клиент думает" создается задача повторного контакта.
- [ ] На стадии "Контроль начала ремонта" создается задача ответственному.
- [ ] Ответственный может заполнить плановую и фактическую дату начала ремонта.
- [ ] На стадии "Ремонт в работе" создается задача контроля окончания.
- [ ] Ответственный может заполнить плановую и фактическую дату окончания ремонта.
- [ ] На стадии "Контроль окончания ремонта" ответственный указывает эксперта.
- [ ] На стадии "Проверка качества" создается задача эксперту.
- [ ] Эксперт фиксирует результат проверки качества в комментарии к задаче.
- [ ] Результат проверки качества переносится в сделку.
- [ ] После успешной проверки качества ответственному автоматически создается задача связаться с клиентом.
- [ ] Ответственный сообщает клиенту о готовности ТС в рамках созданной задачи.

## 6. Права доступа

- [ ] Менеджер Форсайта видит и редактирует сделки своей воронки.
- [ ] Руководитель видит все сделки направления.
- [ ] Эксперт видит задачи и сделки, где он назначен.
- [ ] Мастер СТОА является экстранет-пользователем.
- [ ] Мастер СТОА видит только свои записи/задачи и минимальные данные для дефектовки.
- [ ] Мастер СТОА не получает доступ к воронке CRM и чужим задачам.
- [ ] Мастер СТОА может оставить комментарий к задаче.

## 7. Уведомления

- [ ] Клиент получает подтверждение записи на дефектовку через каскадную рассылку.
- [ ] Клиент получает напоминание о визите через каскадную рассылку.
- [ ] Интеграция обрабатывает `onBookingAdd`, `onBookingUpdate` и `onBookingDelete`.
- [ ] Мобильный телефон мастера берется из профиля экстранет-пользователя.
- [ ] Мастер получает уведомление о новой записи через каскадную рассылку.
- [ ] Мастер получает ссылку на задачу через каскадную рассылку.
- [ ] Повторное событие не создает вторую задачу или повторное уведомление.
- [ ] При ошибке сопоставления каскад не запускается, ответственному создается задача.
- [ ] Отдельный резервный канал уведомлений мастера не требуется.
- [ ] Мастер получает напоминание указать результат дефектовки.
- [ ] Ответственный получает задачу проверить результат дефектовки.
- [ ] Ответственный получает задачи по началу и окончанию ремонта.
- [ ] Эксперт получает задачу по проверке качества ремонта.

## 8. Расчеты

- [ ] Создан товар "Комиссия за ремонт".
- [ ] Ответственный может добавить товар в сделку.
- [ ] В сделке фиксируется сумма комиссии.
- [ ] Ответственный может выставить счет СТОА.
- [ ] В сделке фиксируется статус оплаты от СТОА.
- [ ] После оплаты сделка переводится в "Успешно завершено".

## 9. Пилотная проверка

- [ ] Проведена тестовая сделка с результатом "отказался".
- [ ] Проведена тестовая сделка с результатом "не приехал".
- [ ] Проведена тестовая сделка с результатом "думает".
- [ ] Проведена тестовая сделка с результатом "согласился на ремонт".
- [ ] Проведена тестовая сделка до стадии "Проверка качества".
- [ ] Проведена тестовая сделка до стадии "Расчеты".
- [ ] Проверены уведомления на тестовых участниках.
- [ ] Проверены права доступа мастера СТОА.
- [ ] Проверены перенос, смена мастера и отмена онлайн-записи.
- [ ] Проверены отсутствие пользователя, дубли ID, неактивный пользователь и отсутствие телефона.
- [ ] Замечания пилота внесены в ТЗ или план доработок.
