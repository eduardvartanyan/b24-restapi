- [ ] Сразу после создания записи клиент получает подтверждение по утвержденному шаблону.

## 4. Задачи мастеру и результат дефектовки

- [ ] После записи на дефектовку задача создается непосредственно на найденного экстранет-пользователя.
- [ ] Текст задачи содержит марку и модель ТС, госномер, ФИО клиента, телефон, дату и время, описание повреждений.
- [ ] В теле задачи указан стандартизированный формат ответа мастера.
- [ ] В профиле мастера заполнено поле `Max ID` (`UF_USR_1785748307515`), мастер запустил бота `@id381250859808_bot`.
- [ ] Мастер получает уведомление о новой записи и ссылку на автоматически созданную задачу напрямую в MAX.
- [ ] Уведомление мастера содержит автомобиль, дату и время дефектовки, СТОА и ссылку на созданную задачу.
- [ ] Ссылка из MAX-уведомления открывается под учетной записью экстранет-пользователя.
- [ ] Мастер может оставить комментарий к задаче.
- [ ] Ответ мастера содержит результат, комментарий и ориентировочную стоимость либо отметку "не определена".
- [ ] Ответственному создается контрольная задача с датой дефектовки и чек-листом заполнения результата, комментария и ориентировочной стоимости.

- [ ] После переноса записи в контрольной задаче обновляются дата и время, крайний срок и комментарий, при этом чек-лист сохраняется.

- [ ] На стадии "Контроль начала ремонта" создается задача ответственному.
- [ ] При входе на стадию статус ремонта автоматически устанавливается в значение "Не начат".

- [ ] В задаче есть чек-лист: связаться с СТОА, заполнить плановые даты, подтвердить начало и заполнить фактическую дату.
- [ ] После выполнения задачи сделка автоматически переводится в "Ремонт".
- [ ] При входе на стадию "Ремонт" статус ремонта автоматически устанавливается в значение "В работе".
- [ ] На стадии "Ремонт" создается связанная со сделкой задача контроля окончания со сроком по плановой дате окончания ремонта.

- [ ] Ответственный подтверждает окончание ремонта, заполняет фактическую дату окончания и завершает задачу.
- [ ] После выполнения задачи сделка автоматически переводится в "Проверка качества".
- [ ] На стадии "Ремонт" ответственный указывает в карточке сделки эксперта, выбранного по должностной инструкции.
- [ ] Первым роботом стадии "Проверка качества" статус ремонта автоматически устанавливается в значение "Завершен".
- [ ] Если поле "Эксперт" не заполнено, ответственному создается задание автоматизации на выбор эксперта, а результат сохраняется в сделку.
- [ ] На стадии "Проверка качества" создается задача эксперту.
- [ ] Задача связана со сделкой, а ее крайний срок установлен по полю "Дата проверки качества".
- [ ] Эксперт фиксирует результат проверки качества по утвержденному шаблону: итог, проверенные работы и узлы, замечания, рекомендации клиенту, необходимость и срок повторной проверки.

- [ ] В задаче ответственного есть чек-лист заполнения даты проверки, результата проверки и комментария эксперта.
- [ ] После выполнения задачи ответственного сделка автоматически переводится в "Проверка качества завершена".
- [ ] При результате "Принято без замечаний" ответственному создается связанная со сделкой задача сообщить клиенту о готовности ТС со сроком один день.

- [ ] Ответственный сообщает клиенту о готовности ТС в рамках созданной задачи.
- [ ] После выполнения задачи сделка автоматически переводится в "Расчеты".

## 7. Уведомления

- [ ] Клиентские сообщения о создании, напоминании, переносе и отмене содержат утвержденные данные и отправляются в согласованные моменты.
- [ ] Интеграция обрабатывает `onBookingAdd`, `onBookingUpdate` и `onBookingDelete`.
- [ ] `onBookingUpdate` обрабатывает только запись, ID которой совпадает с полем `ID актуальной онлайн-записи`.
- [ ] При изменении начала или окончания дефектовки обновляются описание и крайний срок существующей задачи; новая задача и новый экземпляр процесса `724` не создаются.
- [ ] При смене ресурса существующая задача переназначается новому мастеру, а поле сделки `СТОА` синхронизируется с компанией нового ресурса.
- [ ] Прежний мастер получает сообщение об отмене назначения, новый мастер — актуальные данные и ссылку на существующую задачу, клиент — сообщение об изменении записи.
- [ ] Процессы напоминаний `738` и `740` перепланируются, а прежние ожидающие экземпляры для задачи или сделки прекращаются.
- [ ] Изменение фиксируется комментарием в задаче и записью в ленте сделки с прежними и новыми значениями.
- [ ] Повторный `onBookingUpdate` с той же сигнатурой `resource_id|date_from|date_to` не меняет задачу и не отправляет уведомления.
- [ ] Ошибка новой связи ресурса или мастера не приводит к частичному обновлению задачи; ответственный получает уведомление о проблеме.
- [ ] `onBookingDelete` завершает задачу с комментарием об отмене, очищает оба технических ID и уведомляет ответственного; сама задача не удаляется, удаление дубля игнорируется.
- [ ] `Max ID` мастера берется из поля `UF_USR_1785748307515` профиля экстранет-пользователя.
- [ ] Мастер получает уведомление о новой записи и ссылку на задачу напрямую в MAX.
- [ ] Повторное событие не создает вторую задачу или повторное уведомление.
- [ ] При ошибке сопоставления или отсутствии `Max ID` сообщение мастеру не отправляется, ответственный получает уведомление о проблеме.
- [ ] Отдельный резервный канал уведомлений мастера не требуется.
- [ ] Через час после планового окончания дефектовки мастер получает напоминание указать результат и завершить задачу.
- [ ] Если задача мастера завершена до времени напоминания, сообщение в MAX не отправляется.
- [ ] Для одной задачи отправляется не более одного напоминания.
- [ ] Ответственный получает задачу проверить результат дефектовки.
- [ ] Ответственный получает задачи по началу и окончанию ремонта.
- [ ] Эксперт получает задачу по проверке качества ремонта.
