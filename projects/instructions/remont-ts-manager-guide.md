# Инструкция менеджера Форсайта по воронке «Ремонт ТС»

Статус документа: основа для последующей детализации и добавления скриншотов.

## 1. Назначение инструкции

Инструкция описывает полный путь сделки: от регистрации клиента до завершения ремонта, проверки качества и расчетов со СТОА.

Основное правило работы: выполняйте связанную задачу и ее чек-лист, заполняйте требуемые поля сделки, затем завершайте задачу. Большинство переходов между стадиями выполняется автоматически.

## 2. Стадии воронки

1. Сделка создана.
2. Запись на дефектовку.
3. Дефектовка.
4. Дефектовка завершена.
5. Клиент думает.
6. Контроль начала ремонта.
7. Ремонт.
8. Проверка качества.
9. Проверка качества завершена.
10. Расчеты.
11. Успешно завершено.
12. Отказ / неуспешно.

Стадии «Дефектовка завершена» и «Проверка качества завершена» являются контрольными. Сделки не должны оставаться на них без решения менеджера.

> [Скриншот 1. Воронка «Ремонт ТС»]

## 3. Создание сделки

1. Откройте воронку «Ремонт ТС».
2. Создайте сделку.
3. Заполните обязательные данные:
   - клиент;
   - марка и модель автомобиля;
   - государственный номер;
   - описание повреждений.
4. При наличии укажите VIN и приложите фотографии повреждений.
5. Проверьте источник и ответственного.
6. Сохраните сделку.

Название сделки формируется автоматически по шаблону `[Имя контакта] [Марка, модель а/м]`.

СТОА при создании сделки не заполняется обязательно: она определяется на стадии «Запись на дефектовку».

> [Скриншот 2. Создание сделки и обязательные поля]

## 4. Запись клиента на дефектовку

После перехода на стадию «Запись на дефектовку» вам создается задача «Подобрать СТОА».

Выполните чек-лист задачи:

1. Уточните у клиента подходящие дату, время и расположение СТОА.
2. Выберите СТОА в карточке сделки.
3. Откройте онлайн-запись и проверьте свободные окна мастеров.
4. Создайте запись на выбранного мастера и время.
5. Убедитесь, что запись создана, и завершите задачу.

После создания онлайн-записи система автоматически:

- создает мастеру задачу;
- отправляет мастеру сообщение в MAX;
- отправляет клиенту подтверждение;
- планирует напоминания;
- переводит сделку на стадию «Дефектовка».

Не переводите сделку на «Дефектовку» вручную сразу после записи: дождитесь автоматической обработки.

## 5. Перенос, смена мастера и отмена записи

Все изменения выполняйте через существующую онлайн-запись.

При переносе даты или времени система обновляет существующие задачи и перепланирует уведомления. Новую задачу вручную создавать не нужно.

При смене мастера система переназначает существующую задачу и при необходимости обновляет СТОА в сделке.

При отмене онлайн-записи система:

- завершает связанные задачи;
- уведомляет клиента и мастера;
- очищает служебные данные;
- возвращает сделку на стадию «Запись на дефектовку».

После отмены выполните новую задачу по подбору СТОА и записи.

> [Скриншот 6. Перенос или отмена онлайн-записи]

## 6. Получение результата дефектовки

После создания онлайн-записи вам также назначается задача «Проверить результат дефектовки».

После дефектовки:

1. Откройте задачу мастера по ссылке из связанной задачи или сделки.
2. Проверьте комментарий мастера.
3. Перенесите данные в сделку:
   - результат дефектовки;
   - комментарий мастера;
   - ориентировочную стоимость ремонта, если она определена.
4. Завершите контрольную задачу.

После завершения задачи сделка переходит на стадию «Дефектовка завершена» и маршрутизируется по результату:

| Результат | Дальнейшее действие |
| --- | --- |
| Отказался | Автоматический переход в «Отказ / неуспешно» |
| Думает | Автоматический переход в «Клиент думает» |
| Согласился на ремонт | Автоматический переход в «Контроль начала ремонта» |
| Не приехал | Сделка остается на контрольной стадии; решение принимает менеджер |
| Перенес запись | Сделка остается на контрольной стадии; решение принимает менеджер |

## 7. Работа с клиентом, который думает

На стадии «Клиент думает» создается задача повторного контакта со сроком три календарных дня.

1. Свяжитесь с клиентом.
2. Получите окончательное решение.
3. Измените поле «Результат дефектовки» только на одно из значений:
   - «Согласился на ремонт»;
   - «Отказался».
4. Завершите задачу.

Если окончательное решение не получено, цикл повторного контакта запускается снова.

> [Скриншот 9. Задача повторного контакта]

## 8. Контроль начала ремонта

На стадии «Контроль начала ремонта» создается задача без крайнего срока.

1. Свяжитесь с СТОА.
2. Заполните плановые даты начала и окончания ремонта.
3. Дождитесь фактического начала ремонта.
4. Заполните фактическую дату начала ремонта.
5. Завершите задачу.

Не завершайте задачу до подтверждения фактического начала ремонта.

После завершения задачи сделка автоматически перейдет на стадию «Ремонт».

> [Скриншот 10. Поля и задача контроля начала ремонта]

## 9. Контроль окончания ремонта

На стадии «Ремонт» создается задача «Проконтролировать окончание ремонта».

1. Поддерживайте связь со СТОА.
2. При необходимости уточняйте плановую дату окончания.
3. После завершения ремонта заполните фактическую дату окончания.
4. Выберите эксперта в поле «Эксперт».
5. Завершите задачу.

После завершения задачи сделка автоматически перейдет на стадию «Проверка качества».

> [Скриншот 11. Задача контроля окончания ремонта]

> [Скриншот 12. Выбор эксперта]

## 10. Фиксация результата проверки качества

Эксперт получает отдельную задачу и оставляет результат в комментарии. После этого вам создается задача «Зафиксировать результат проверки качества».

1. Проверьте комментарий и вложения эксперта.
2. Заполните в сделке:
   - дату проверки качества;
   - результат проверки качества;
   - комментарий эксперта.
3. Завершите задачу.

Дальнейший маршрут:

| Результат | Дальнейшее действие |
| --- | --- |
| Принято без замечаний | Создается задача сообщить клиенту о готовности ТС |
| Есть замечания | Сделка возвращается в «Ремонт» |
| Требуется повторная проверка | Сделка возвращается в «Проверка качества» |
| Поле не заполнено или значение неизвестно | Сделка остается на контрольной стадии |

> [Скриншот 13. Результат эксперта и поля проверки качества]

## 11. Сообщение клиенту о готовности ТС

При успешной проверке качества вам создается задача со сроком один день.

1. Свяжитесь с клиентом.
2. Сообщите о завершении ремонта и успешной проверке качества.
3. Передайте рекомендации эксперта.
4. Согласуйте получение автомобиля.
5. Зафиксируйте результат разговора в комментарии задачи.
6. Завершите задачу.

После завершения задачи сделка перейдет на стадию «Расчеты».

## 12. Расчеты со СТОА

1. Откройте вкладку «Товары» сделки.
2. Добавьте товар «Комиссия за ремонт ТС».
3. Укажите ненулевую сумму комиссии.
4. Проверьте поле «Сумма комиссии» в сделке.
5. Создайте связанный счет СТОА штатной командой Битрикс24.
6. Контролируйте оплату по статусу счета.
7. После оплаты вручную переведите сделку в «Успешно завершено».

Отдельное поле статуса оплаты в сделке не используется.

## 13. Служебные поля

Не изменяйте вручную следующие поля:

- ID актуальной онлайн-записи;
- ID задачи мастера;
- ID задачи контроля дефектовки;
- сигнатура онлайн-записи.

Они заполняются интеграцией и нужны для защиты от повторных задач и уведомлений.

## 14. Типовые ошибки

| Ситуация | Действие менеджера |
| --- | --- |
| Сделка не перешла на «Дефектовку» после записи | Проверьте ленту сделки и уведомления об ошибке; не создавайте вторую запись |
| Мастеру не создалась задача | Сообщите администратору ID сделки и имя выбранного ресурса |
| Клиент или мастер не получил сообщение | Проверьте ленту сделки и передайте ошибку администратору |
| Сделка осталась на красной контрольной стадии | Проверьте обязательные поля и примите ручное решение |
| Нужно перенести запись | Измените существующую онлайн-запись, не создавайте новую |
| Нужно отменить запись | Отмените онлайн-запись и дождитесь автоматического возврата сделки |

## 15. Ежедневный чек-лист менеджера

- [ ] Нет необработанных сделок на стадии «Дефектовка завершена».
- [ ] Нет необработанных сделок на стадии «Проверка качества завершена».
- [ ] Выполнены задачи с наступившим сроком.
- [ ] В открытых сделках заполнены актуальные даты ремонта.
- [ ] Перед проверкой качества выбран эксперт.
- [ ] На стадии «Расчеты» добавлена комиссия и создан счет.
- [ ] Служебные поля не редактировались вручную.
