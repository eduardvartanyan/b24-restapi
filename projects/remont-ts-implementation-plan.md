# Проект "Ремонт ТС": план внедрения

Дата создания: 2026-06-17
Дата актуализации: 2026-07-28

Цель плана: разложить настройку CRM-воронки в облачном Битрикс24 на управляемые этапы с учетом текущей версии ТЗ.

## 1. Подготовка

1. Зафиксировать исходные условия: облачный Битрикс24, тариф "Профессиональный".
2. Зафиксировать, что "Онлайн-запись" доступна в портале.
3. Зафиксировать, что мастера СТОА могут использоваться как ресурсы бронирования или специалисты.
4. Проверить текущую модель счетов, оплат и товаров в CRM.
5. Согласовать список участников пилота: менеджеры, эксперты, СТОА, мастера.
6. Согласовать минимальный набор данных в задаче мастеру.

Результат этапа: целевой процесс строится на онлайн-записи, специалистах онлайн-записи, отдельных графиках приема мастеров и задачах с комментариями мастера.

## 2. Структура CRM

1. Создать тестовую воронку "Ремонт ТС".
2. Создать стадии воронки по файлу `projects/remont-ts-reference.md`.
3. Создать пользовательские поля сделки.
4. Настроить обязательность ключевых полей по стадиям.
5. Создать товар "Комиссия за ремонт".

Результат этапа: менеджер может создать тестовую сделку и провести ее вручную по стадиям.

## 3. Справочник СТОА

1. Создать тип CRM-компании "СТОА".
2. Создать поля карточки СТОА: название, адрес, телефоны, график работы, условия комиссии, ответственный, комментарий.
3. Завести две тестовые СТОА.
4. Завести по два специалиста онлайн-записи для каждой тестовой СТОА.
5. Создать в сделке отдельное поле "СТОА" с привязкой к компании CRM.
6. Для каждого специалиста указать название компании СТОА как тип ресурса, а имя мастера — как название ресурса.
7. Подготовить инструкцию для самостоятельного создания СТОА, специалистов и их графиков пользователями.

Результат этапа: менеджер выбирает компанию с типом "СТОА" в отдельном поле сделки и определяет принадлежность специалиста по типу ресурса в онлайн-записи.

## 4. Онлайн-запись и занятость мастеров

Основной вариант: "Онлайн-запись" в CRM Битрикс24.

1. Настроить тестовую услугу "Дефектовка ТС".
2. Настроить мастеров СТОА как ресурсы бронирования или специалистов.
3. Настроить отдельные графики приема по каждому мастеру.
4. Проверить отображение занятости всех мастеров в интерфейсе менеджера.
5. Проверить ручное создание записи менеджером из CRM-сделки.
6. Проверить фиксацию СТОА в поле сделки, а специалиста, даты и времени — в связанной онлайн-записи.
7. Проверить отправку подтверждения записи клиенту через каскадную рассылку.
8. Проверить отправку уведомления мастеру через каскадную рассылку со ссылкой на автоматически созданную задачу.
9. Проверить запуск роботов от создания онлайн-записи.
10. Проверить, что специалист, дата, время и адрес СТОА доступны шаблонам задач, срокам контрольных задач и сообщениям без отдельных пользовательских полей сделки.
11. Настроить обработку переноса и отмены записи, включая актуализацию ранее созданных задач и сообщений.

Результат этапа: менеджер видит занятость мастеров, выбирает свободное окно и фиксирует запись на дефектовку в сделке.

## 5. Задачи мастеру и результат дефектовки

1. Настроить автоматическое создание задачи мастеру или ответственному после записи на дефектовку.
2. Включить в текст задачи данные по шаблону из ТЗ: марка, модель, госномер, клиент, телефон и варианты результата.
3. Проверить, что мастер получает ссылку на задачу через каскадную рассылку.
4. Проверить, что мастер может оставить комментарий к задаче.
5. Описать формат комментария мастера.
6. Настроить ручной или автоматический перенос результата из комментария в поле "Результат дефектовки".
7. Настроить переход сделки по результату дефектовки.

Результат этапа: результат дефектовки попадает в сделку, а сделка переходит в корректную стадию.

## 6. Права доступа

1. Создать тестовый сценарий доступа для мастера.
2. Проверить доступ мастера к задаче.
3. Проверить, какие данные клиента и сделки видит мастер.
4. Проверить, что мастер не получает лишний доступ к CRM.
5. Проверить, что мастер может оставить комментарий к задаче.
6. Зафиксировать допустимую модель доступа.

Результат этапа: подтвержден безопасный способ взаимодействия с мастерами СТОА без роли полноценного пользователя CRM.

## 7. Роботы и задачи по стадиям

1. На стадии "Сделка создана" проверить обязательные поля клиента и ТС.
2. На стадии "Запись на дефектовку" поставить ответственному задачу подобрать СТОА, свободного мастера и время.
3. На стадии "Запись на дефектовку" создать онлайн-запись и задачу мастеру.
4. На стадии "Дефектовка назначена" поставить ответственному контрольную задачу проверить результат.
5. По результату дефектовки перевести сделку в нужную стадию.
6. На стадии "Клиент думает" поставить задачу повторного контакта.
7. На стадии "Контроль начала ремонта" поставить задачу ответственному уточнить старт ремонта.
8. На стадии "Ремонт в работе" поставить задачу контроля плановой даты окончания.
9. На стадии "Контроль окончания ремонта" поставить задачу ответственному уточнить завершение ремонта и выбрать эксперта.
10. На стадии "Проверка качества" поставить задачу эксперту.
11. На стадии "Расчеты" поставить задачу контроля счета и оплаты.

Результат этапа: сделка сопровождается задачами по логике текущего ТЗ.

## 8. Уведомления

1. Настроить подтверждение записи клиенту через каскадную рассылку.
2. Настроить напоминание клиенту о дефектовке через каскадную рассылку.
3. Настроить уведомление мастера о новой записи через каскадную рассылку.
4. Проверить отправку ссылки на задачу мастеру через каскадную рассылку.
5. Настроить уведомление ответственному о необходимости проверить результат дефектовки.
6. Настроить уведомление эксперту о задаче проверки качества.

Результат этапа: клиент, мастер, ответственный и эксперт получают уведомления по своим действиям; отдельный резервный канал для мастера не требуется.

## 9. Расчеты

1. Проверить карточку товара "Комиссия за ремонт".
2. Проверить добавление товара в сделку на стадии "Расчеты".
3. Проверить фиксацию суммы комиссии.
4. Проверить выставление счета СТОА ответственным.
5. Проверить перевод сделки в "Успешно завершено" после оплаты.

Результат этапа: стадия "Расчеты" работает по текущему ТЗ.

## 10. Пилот

1. Провести тестовую сделку с результатом "отказался".
2. Провести тестовую сделку с результатом "не приехал".
3. Провести тестовую сделку с результатом "думает".
4. Провести тестовую сделку с результатом "согласился на ремонт".
5. Провести тестовую сделку до стадии "Расчеты".
6. Собрать замечания менеджеров, экспертов и мастеров.
7. Исправить поля, стадии, задачи и уведомления.

Результат этапа: процесс готов к запуску на подключенных СТОА.

## 11. Запуск

1. Перенести настройки из тестового режима в рабочий.
2. Обучить менеджеров и экспертов.
3. Подключить СТОА и мастеров.
4. Запустить процесс.
5. Первые 1-2 недели вести ежедневный контроль ошибок и ручных обходов.

Результат этапа: воронка "Ремонт ТС" работает в регулярном режиме.
