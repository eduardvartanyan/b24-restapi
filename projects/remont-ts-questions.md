# Проект "Ремонт ТС": открытые вопросы

Дата создания: 2026-06-17
Дата актуализации: 2026-08-08

Этот файл хранит вопросы, которые нужно уточнить перед финальной настройкой CRM-воронки в облачном Битрикс24. Вопросы синхронизированы с текущими файлами `projects/remont-ts-tz.md` и `projects/remont-ts-reference.md`.

## 1. Битрикс24 и онлайн-запись

| Вопрос | Статус | Комментарий |
| --- | --- | --- |
| Какой тариф Битрикс24 используется сейчас? | Закрыт | Облако, профессиональный тариф. |
| Доступна ли функция "Онлайн-запись" в текущем портале? | Закрыт | Да, доступна. |
| Можно ли завести мастеров СТОА как ресурсы бронирования или специалистов? | Закрыт | Да. Мастер создается как ресурс онлайн-записи и как экстранет-пользователь. Ресурс, СТОА и пользователь связываются через закрытый универсальный список; отдельное поле мастера в сделке не создается. |
| Можно ли менеджеру Форсайта вручную создавать онлайн-запись из CRM-сделки? | Закрыт | Да, можно. Клиент сам не должен пользоваться публичной формой. |
| Можно ли хранить запись онлайн-записи в карточке сделки? | Закрыт | Да, можно. |
| Можно ли запускать автоматизацию от создания или изменения онлайн-записи? | Закрыт | Штатный запуск подтвержден для создания записи. Для интеграции используются REST-события `onBookingAdd`, `onBookingUpdate` и `onBookingDelete`. |
| Нужны ли в сделке отдельные поля мастера, адреса СТОА, даты и времени дефектовки? | Закрыт | Нет. Мастер, дата и время хранятся в онлайн-записи, адрес — в связанной карточке СТОА. Для работы интеграции добавляются только служебные поля `ID актуальной онлайн-записи` и `ID задачи мастера`; они не дублируют бизнес-данные записи. |

## 2. СТОА и мастера

| Вопрос | Статус | Комментарий |
| --- | --- | --- |
| Какие поля должны быть в карточке СТОА? | Закрыт | Для первого этапа: название, адрес, телефоны, график работы, условия комиссии, ответственный, комментарий. |
| Сколько СТОА планируется подключить на первом этапе? | Закрыт | Для сдачи проекта создаются две СТОА. Далее пользователи создают СТОА самостоятельно по инструкции. |
| Сколько мастеров будет у каждой СТОА? | Закрыт | Для сдачи проекта создаются по два мастера для каждой из двух СТОА. Далее пользователи создают мастеров самостоятельно по инструкции. |
| У каждого мастера должен быть отдельный график приема? | Закрыт | Да, у каждого мастера должен быть отдельный график приема. |
| Где хранить СТОА: в компаниях CRM или в отдельном смарт-процессе? | Закрыт | СТОА хранятся в компаниях CRM с отдельным типом "СТОА". Сделка связывается с ними через отдельное пользовательское поле "СТОА". |
| Как связать специалиста онлайн-записи с конкретной СТОА? | Закрыт | Название компании СТОА указывается как тип ресурса, имя мастера — как название ресурса. Например: тип "Кузя", ресурс "Илья Иванов". |

## 3. Задачи мастерам

| Вопрос | Статус | Комментарий |
| --- | --- | --- |
| Как именно мастер получает ссылку на автоматически созданную задачу? | Закрыт | REST-обработчик получает ID ресурса из онлайн-записи, находит ID экстранет-пользователя и запускает для сделки бизнес-процесс `724` с параметрами `user_id`, `date_from` и `date_to`. Бизнес-процесс создает задачу, получает мобильный телефон пользователя и запускает шаблон каскадной отправки `734` с данными дефектовки и ссылкой на задачу. |
| Может ли мастер открыть задачу и оставить комментарий без доступа к лишней CRM? | Закрыт | Да. Задача назначается непосредственно экстранет-пользователю с ограниченными правами. |
| Какие данные мастер должен видеть в задаче? | Закрыт | Марка и модель ТС, госномер, ФИО клиента, телефон, дата и время дефектовки, описание повреждений. |
| Как результат из комментария к задаче будет переноситься в поле "Результат дефектовки"? | Закрыт | На старте ответственный за сделку вручную переносит результат, комментарий мастера и ориентировочную стоимость в поля сделки. |
| Нужна ли стандартизированная форма комментария мастера? | Закрыт | Да. В теле задачи указывается обязательный формат ответа: результат, комментарий, ориентировочная стоимость. |
| Сохраняет ли бизнес-процесс `724` ID созданной задачи в сделку? | Закрыт | Проверено: после создания задачи ее ID сохраняется в `UF_CRM_1786012024`. |
| Какие параметры времени передаются в бизнес-процесс `724`? | Закрыт | `date_from` содержит дату и время начала дефектовки, `date_to` — дату и время окончания дефектовки и крайний срок задачи. |

## 4. Клиентские уведомления

| Вопрос | Статус | Комментарий |
| --- | --- | --- |
| Через какой канал клиент получает подтверждение записи на дефектовку? | Закрыт | Через каскадную рассылку сразу после создания онлайн-записи, по утвержденному нейтральному шаблону из раздела 8 ТЗ. Обращение по имени не используется, поскольку поле "Имя" контакта содержит полное ФИО. |
| Через какой канал клиент получает напоминание о визите? | Закрыт | Через каскадную рассылку за 24 часа до визита. Если запись создана менее чем за 24 часа до дефектовки, отдельное напоминание не отправляется. |
| Кто сообщает клиенту о готовности ТС после проверки качества? | Закрыт | С клиентом связывается ответственный за сделку. При результате "Принято без замечаний" ему автоматически создается связанная со сделкой задача со сроком один день; после ее выполнения сделка переводится в "Расчеты". |

## 5. Внешний канал для мастеров

| Вопрос | Статус | Комментарий |
| --- | --- | --- |
| Какой внешний канал используется для уведомления мастера? | Закрыт | Каскадная рассылка. |
| Если используется МАКС, есть ли API или готовая интеграция с Битрикс24? | Закрыт | Каскадная рассылка уже настроена. Дополнительно требуется REST-обработчик, который связывает онлайн-запись, экстранет-пользователя, задачу и каскад. |
| Какие данные можно отправлять мастеру во внешний канал? | Закрыт | Уведомление о назначении дефектовки и ссылка на задачу. |
| Нужен ли резервный канал уведомлений мастера? | Закрыт | Нет. Резерв внутри каскада уже задан: Макс -> WhatsApp -> Telegram -> SMS. |

## 6. Ремонт и проверка качества

| Вопрос | Статус | Комментарий |
| --- | --- | --- |
| Кто подтверждает факт начала ремонта: мастер, клиент или ответственный Форсайта? | Закрыт | Начало ремонта подтверждает ответственный за сделку: он заполняет фактическую дату начала и завершает контрольную задачу, после чего робот переводит сделку в "Ремонт". |
| Кто подтверждает окончание ремонта? | Закрыт | Ответственный заполняет фактическую дату окончания ремонта и завершает контрольную задачу. После этого робот переводит сделку в "Проверка качества", где первый робот устанавливает статус ремонта "Завершен". |
| Как ответственный выбирает эксперта по проверке качества? | Закрыт | Порядок выбора определяется должностной инструкцией и не входит в данное ТЗ. На стадии "Ремонт" ответственный выполняет пункт чек-листа задачи контроля окончания и указывает выбранного эксперта в карточке сделки. |
| Какие данные эксперт должен фиксировать в комментарии к задаче проверки качества? | Закрыт | Заказчик согласовал формат: итог проверки, проверенные работы и узлы, выявленные замечания, рекомендации клиенту, необходимость и срок повторной проверки. |
| Нужно ли унифицировать термин проверки качества в ТЗ? | Закрыт | Да, в проектных документах используется только термин "Проверка качества". |
